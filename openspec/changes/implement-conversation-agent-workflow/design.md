## Context

用户授权完整九步计划。以已确认计划文档为详细边界；主助手是统一对话与决策入口，四类专业 Agent 是实际执行能力，沿用已有准入与结果核实。

## Decisions

- SQLite Worker 维护 conversation、message、turn、action 和 authorization，所有公开读取按主体／项目重新授权；消息按单调序号有界读取。
- 每次模型决策绑定准确输入版本，异步返回与动作应用再次检查；同一会话决策串行，领域工作按原 DAG 运行。
- 模型发送前记录原请求；发送后未知不重新调用，先核实原记录。回复与动作只应用一次。
- 计划模式保留准确人工确认；执行模式使用独立范围授权，不能写伪造人工确认。
- 原工作台 Run 链接继续兼容，新会话主区呈现自然回复与结果；详情按需查看。
- 配置保存与实际运行能力分开。缺模型、资源或结果时显示准确阻塞，不能以文案冒充执行。

## Validation

按计划中的模式、身份、版本、重复提交、丢回执、迟到响应、控制、原恢复、宽窄屏与迁移矩阵实际验证。每个步骤完成后记录证据，未验证的真实资源不签认。

## Implementation notes

迁移55只新增会话及独立授权，旧schema读取通过planAdmissionTable保留人工确认语义。范围采用遵守真实暂停／副作用收尾，已记录恢复先处理暂停期间保存的输入；本轮不实现绕过暂停的咨询执行。消息采用有界按序轮询，完整自然回复可靠保存后展示，原Run事件／专业流式输出保持兼容。

真实模型核验发现已存完整chat/completions地址被重复追加。共享modelApiBase兼容API根和完整完成地址，原配置只在读取时规范化，不改写原密钥；保存、模型列表、连接测试及Runtime统一使用同一API根。增加真实HTTP前缀和旧配置不重写验证。

开发证据与实际环境结果分别登记。实际模型咨询核验与真实研发／Linux隔离验收是不同事实，执行资源未配置时禁止声称正在实现。
