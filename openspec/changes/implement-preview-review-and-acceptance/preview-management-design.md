## Exact candidate preview management entry

Parent P1-07 / 2.3 and 5.1. Add a private authenticated HTTP management entry under an exact Run/candidate. The next React workbench entry will consume this API; this increment does not count a complete workbench as delivered.

Explicit trusted startup previewPolicies selects one previously committed original policy per project for new dataset/start intents. Default is off; it is not proof that a Runner or access gateway is configured/healthy. Existing original operations and member read history remain accessible when this selection is removed. Dataset/preview consumers remain independent and must be explicitly installed by trusted composition.

GET returns a bounded current-member projection in one synchronous control writer call: exact candidate/manifest/qualification, immutable delivery data plan and source, Run resource revision, owner/current/configuration capabilities, independently paged datasets/previews (1–20, default10) with stable original rowid cursors. Dataset operation state is visible, but storage keys, policy body, backend/Runner/instance/endpoint, request bodies and proofs are not. Reads never dispatch, refresh health or accept.

Owner POST creates only original dataset intent or, after dataset READY, exact preview intent. Standard UUID idempotency/run scope and strong If-Match apply. Start body fixes original dataset and expiresAt (60seconds–24hours at first commit), not a URL, image or storage path. Dataset creation keeps the candidate's existing INITIAL/isolated accepted-source data decision and cannot pick a replacement/migration here. An original request remains recoverable with identical body/key/old If-Match after configuration removal. Stop requires a separate explicit STOP_PREVIEW confirmation, preview revision and impactReviewHash, original preview scope and fixed USER reason. It preserves dataset and rejects Release ownership. URL candidate/run authorization and current member checks apply before lookup and response; historical candidates are readable but cannot obtain new dataset/start intents.

Contracts/OpenAPI and actual HTTP/control Worker tests cover schemas, scope/permissions, defaults, conditionals/idempotency, ACK loss/reopen, redaction, pending/UNKNOWN history, accepted protection and independent preparation/start/stop execution. Actual local files/HTTP are distinguished from upstream Git/OCI and controlled container facts. Enterprise identity, real Linux and the full successor chain stay separate.
