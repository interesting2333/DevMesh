## Context

见 proposal.md。依据 design/04 §1–2、§6–8，模板数据库与平台存储分离；生成应用只能在独立 Runner 执行。已只读核对 deepseek-harness：Web 应用使用 React 18／TypeScript、Vite、Vitest、Playwright；其应用和根目录存在不同 Vite 版本。本变更选择兼容的精确版本并通过独立安装与构建验证，不拷贝整个 harness。

## Goals / Non-Goals

**Goals:** 可独立复制的固定模板、端到端任务 CRUD、可恢复的业务数据、可审查的检查与覆盖范围。

**Non-Goals:** 不把本模板当 DevMesh 工作台；不共享平台 Cookie／本地存储／数据库，不在本机运行任意用户生成代码，不提前宣称 runsc 验收或人工接受。

## Decisions

1. `templates/web-crud-v1` 是独立 pnpm 项目，有自己的 package.json、锁文件、Node／pnpm 约束与 tsconfig。前端 React 18＋Vite，后端 Express 5＋Node 24 SQLite Worker；全部第一方业务源码为 TypeScript。不引入需要额外 Python 或数据库服务的依赖。
2. 模板能力清单固定 templateId／revision、支持的检查、业务源码覆盖 glob、数据 schema 和运行环境。实际镜像 digest 未构建时为 null／PENDING，不能被 Runner 当成已批准镜像。SDK／平台包不作为模板运行依赖，复制后能独立安装构建。
3. 任务实体含内部 ID、标题、说明、todo/doing/done、revision 与时间。标题按 Unicode 码点限定 120，说明 4,000；非法字段、空标题、有界体积与未知状态拒绝。用户文本通过 React 文本渲染，不插入 HTML。
4. SQLite Worker 是应用数据单写者，WAL／FULL，正式初始迁移与完整性检查。数据根必须是显式的独立 dataset，布局标记和实例 ID 防止误收编；不能把缺失数据库静默视为新数据。所有写请求携带稳定幂等键，同键不同请求冲突；更新／删除带版本条件，事务内写记录及回执。没有网络／文件 I/O 混入事务。
5. API 同源、无通配 CORS，默认 loopback。有界 JSON 请求、输入校验和稳定错误码，不返回主机路径或堆栈。只读模式阻止新写请求但仍可查询；实际预览授权和最终数据迁移写门由后续网关承接，模板不持有平台凭据。
6. UI 提供三列、计数、新建／编辑／状态选择、确认删除、加载与错误反馈；等待写入时避免重复提交，冲突时重新读取并保留明确错误。刷新后从后端读取，后端重启后恢复同一 dataset 的记录，不以浏览器内存冒充保存。
7. 构建前后端分别产物；Vitest 使用真实临时应用数据库／HTTP 验证 API 与重启，前端用 DOM 交互验证。覆盖率包含所有业务源码，初始阈值行 80%／分支 70%，不因报告不达标临时缩小分母。Playwright 验证三列 CRUD、刷新保留、失败反馈和实际服务停止；结果与配置哈希保存。
8. 固定仓库模板源码的构建、静态校验和第一方测试可独立执行；它们不授予运行任意用户产物的权限，也不作为容器隔离证据。目标 Runner 的离线安装缓存、镜像构建、真实执行和停止另列未执行项，资源具备前不代填 digest 或通过结论。

## Risks / Trade-offs

- [目标 Runner 与镜像缺失] → 先交付固定源码与可独立执行的检查，真实 runsc／镜像专项保持待执行。
- [前后端版本或测试工具不兼容] → 参照 harness 方向，实际安装锁定兼容版本，独立锁文件与类型／构建检查共同验证。
- [SQLite 文件误用或竞争写入] → 显式数据根、布局标记、单写者与乐观版本，重启保留原数据库；动态数据切换由平台数据网关接续。
- [覆盖或浏览器依赖缺失] → 保留真实失败／缺项，禁止用格式校验替代；通过后记录实际命令和环境。

## Migration Plan

新增模板及校验命令，不改变控制面迁移。模板自身仅初始化应用 schema v1；后续升级通过显式数据迁移与备份，不删除原 dataset。停用模板只停止服务，代码／业务数据保留；清理与接受仍由平台流程决定。
