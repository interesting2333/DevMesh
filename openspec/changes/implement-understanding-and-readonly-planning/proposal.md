## Why

父工作包 P1-02，依据 D1 §8、D2 §2～3、D3 §2～3、D5 产品表和 U05～U08／I04～I06。P1-01 已能持久保存原文和理解作业，但尚无带来源的需求版本、问题／部分回答、解释重试及确认前规划；现有实施 Attempt 依赖已确认计划，不能直接用于产生这个计划。

## What Changes

- 增加准备阶段专属持久宿主、只读许可、模型输入／输出索引、用量、原操作核实和 Run 控制代际检查；不伪造已确认实施计划或 Invocation。
- 保存有来源且不可变的需求理解、问题版本、用户部分回答与解释作业；重试固定原答案集合，暂停只保存。
- 产品／架构采用严格结构化契约，矛盾显式引用双方来源，未答必要问题阻止实施；架构仅产生未确认草稿。
- 暴露当前权限下的理解查询、回答、解释重试；默认无 Provider 时原作业保持等待且可见，不自动使用测试模型。
- 用真实数据库、内容文件、HTTP、进程中断及受控 Provider 验证代码；企业身份、真实模型与 Runner 专项沿用未执行边界。

## Capabilities

### New Capabilities

- `understanding-and-readonly-planning`: 确认前只读准备执行、可追溯理解、版本化澄清与解释重试、不可自动实施的计划草稿。

### Modified Capabilities

无。P1-01 增量变更尚未归档；本变更按其保存的输入及作业继续处理，不宣称父工作包前置已通过。

## Impact

涉及 contracts、storage-sqlite 新迁移、独立准备 Runtime、input-api、platform-core 的可选组合、OpenAPI、测试和台账。复用已有 ModelProvider／内容存储及官方 A2A 传输；严格区分准备宿主与实施 Attempt，会话外键保持真实。无新增供应商依赖或真实凭据，无自动执行生成代码；G0／正式 P1-01 状态不变更为通过。
