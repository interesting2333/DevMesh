## Design

1. 部署通过服务端配置指定设置管理员。管理员在工作台人工填写 Endpoint 和凭据引用。内置 Endpoint 策略支持 GitHub 与 Context7，部署者可追加信任的 Endpoint、绑定凭据及只读工具清单。
2. 使用 Streamable HTTP 和环境变量提供的 Bearer 凭据。连接发现分页读取目录，在同一会话内校验版本和 schema 哈希。本人最近一次发现结果用于校验新授权。
3. 设置和有界审计记录同文件原子保存。服务重启加载已启用项。停用和删除立即拒绝新调用。发现、运行状态和角色授权分开。
4. 工作流角色快照显式列出工具名。宿主复核当前执行许可和项目。GitHub 额外核对仓库和多操作工具的方法。外部服务收到标准参数，调用结果经过脱敏和大小限制后交给现有 Runtime。
5. 每次调用在新的标准 MCP 会话内检查当前目录哈希，再发送工具请求。冻结哈希变化时转入待重新确认。首期只执行批准的只读工具。
6. 设置列表提供独立的启停开关。停用立即拒绝新调用。启用复用连接验证和原有工具授权，成功保存后显示待重启。缺少授权或工具目录变化时，列表显示提示，管理员通过独立的编辑按钮重新确认。新建服务保存为停用，可从列表启用。
7. 内置策略为 Atlassian 的 Jira 查询、Linear 的工单查询和 Exa 的公开网页搜索提供预设地址和只读工具。三项服务均需绑定 DevMesh 项目。Exa 通过 `x-api-key` 认证。Atlassian 使用固定的 `tools=all` 参数发现独立工具。
8. 本机预览通过设置管理员手工添加 Playwright MCP，并保存显示名称、浏览器、无头模式和启用状态。启用时通过 stdio 连接固定版本的微软 Playwright MCP，发现工具并启动浏览器。停用、删除或关闭预览时关闭连接与进程。修改运行中的浏览器配置会重新启动进程。
9. 本机 Playwright MCP 设置项展示服务状态以及添加、编辑和启停操作。开发者可用任务看板脚本运行自检并生成截图、快照和报告。
