## Context
原执行 workspace 表达隔离的代码副本，不能承担用户可编辑的任务分组。新增 workbench_spaces，与物理分配分别管理。

## Decisions
1. 空间归属用户；现有数据按 owner 原子迁入默认空间。新用户 GET 使用显式虚拟默认实体，第一次写事务落库，读取无副作用。
2. 空间编辑和任务迁移比较 revision，当前身份重新鉴权；最后一个空间和非空空间不能删除。
3. 对话冻结 directory_binding_json；后续目录编辑、空间迁移均不改写它。Run 来源与输入项目／迭代在同一事务登记。
4. 本地目录仅限配置 trusted roots；检查 canonical path、Git 根和文件身份。模型材料来自冻结 commit，限制大小、文件数，排除敏感路径，不能执行仓库钩子／过滤器。执行通过已有受控 Git 副本导入接口，实际 Runner 能力单独判断。
5. 空间管理原请求使用独立 IndexedDB 日记，避免混入原会话控制恢复。请求 UUID／正文先提交本机事务，丢回执显式 lookup 原 key 后才允许同原文重试。
6. 本机草稿按空间和会话分离，旧草稿与附件一次归入原默认空间，原命令正文不补写新字段。切换前保存，后台 Run 继续。

## Validation
覆盖升级／回滚、跨用户、过期版本、原回执恢复、活动任务迁移拒绝、冻结目录和实际 Git 材料、桌面切换／草稿／附件／管理。正式 Linux 执行链和产品阶段门槛不能用本次 Windows 增量验证替代。
