## Context

父工作包P1-08；动机见proposal。设计依据D3 §4事件、§5状态归属、§6身份，实施文档P1-08与T08。已检查input-api/index.ts、input-domain.ts、contracts/input.ts、events.ts和现有React页面／浏览器测试：原项目、消息、快照、分页事件、理解与计划API可复用；工作台、IndexedDB和WebSocket挂接尚不存在。已有独立交付页面不能视为完整产品路径。

## Goals / Non-Goals

**Goals:** 用原服务端权限和状态建立贯通工作台；优先实现受保护入口和持久输入，再接实际理解／计划／交付上下文及事件续读。浏览器本地事务和未知命令恢复必须先于新的写入口。

**Non-Goals:** 本变更不实现企业OIDC、不代替模型或Linux Runner，不为尚未实现的控制／配置命令生成按钮或模拟成功，也不因页面存在推进正式门槛。P2的历史导入／回放保留独立能力边界。

## Decisions

### 宿主与依赖

继续使用input-api内的Express受保护路由、React 18、Zod、现有tsdown浏览器构建与原生IndexedDB。页面位于`/api/v1/workbench/view`，脚本同受保护路由；启动默认身份缺失仍503，不能自动授予本地owner。沿用现有Host／Origin／Cookie／loopback检查、no-store、nonce CSP与响应前权限复核。初始数据只包含当前可信principalId和经验证的显示上下文，不包含密钥、内部路径或能力授权。

工作台所有业务读取／提交带`X-DevMesh-Principal`，值绑定HTML中的可信主体。Input API对提供此可选头的请求先核对当前resolver主体，错配403且不写正文或operation，重复头拒绝；旧客户端未提供时沿用原行为。这样避免同一浏览器换账号后，旧页把另一主体的本地原命令交给新身份执行。当前页面因此失效时清受保护投影，重进取得新主体；不能从消息作者或客户端任意输入推断账号。

复用原API可避免再建一套写语义。单独应用框架／新状态库会增加部署和依赖，当前无需引入；不使用sessionStorage代替跨刷新／多页要求。

### 本地存储与原命令

浏览器数据库版本独立于控制库，使用事务型drafts和commands两个store。上下文键由规范数组编码`[principalId,projectId,runId,formId,basisRevision]`，避免拼接碰撞。首次覆盖project与message表单；后续答案、计划反馈和新任务沿用同样不变量扩展严格schema，不接受任意URL／方法的通用命令。

草稿保存文本、表单值、稳定clientDraftId、本地revision和时间。每次写在同一readwrite事务内比较预期本地revision，成功提交才算已保存在本机。多页陈旧写必须报冲突并保留当前内存输入，不能最后写入静默覆盖。页面按输入顺序排空写队列；切项目／Run先排空，失败保留原上下文并提供重试／明确放弃；beforeunload保护未持久输入。旧依据草稿可展示参考，不自动套当前条件。

commands保存严格原UUID、主体／上下文、原scope／路径／正文／If-Match及创建时间；入队事务同时确认准确草稿revision和没有未决命令。先提交本地事务再HTTP，事务失败零网络写。原信封固定，后续只更新观察／回执，不改正文或生成替代键。未知命令锁住同表单的新提交。多页入队竞争仅一个成功，原请求不被另一页覆盖。

commands的稀疏唯一pendingForm索引覆盖主体／项目／Run／表单，故即使Run依据变化，也不能绕过旧未决提交；原草稿保留准确basisRevision。仅核实成功输入回执后在同一事务释放锁并清空对应原草稿，新输入生成新clientDraftId，原正文在命令历史保留。非成功／未知观察保留锁；不能把处理中的理解作业误当输入命令尚未提交。后续需扩展明确拒绝后的处置时单独验证，不清库解锁。

页面重开先读日记，GET原operation lookup；404仅表示当前未查到，不能视为安全生成新请求的许可。用户可明确使用完全相同原信封继续提交；未知或传输失败不自动POST。新请求的明确条件／schema拒绝与已保存消息、处理WAITING和最终结果分别显示；受理不显示为模型分析完成。只有核实原命令结果后解除未决指针，保留原历史。服务端当前权限、If-Match和幂等仍是最终依据，本地数据不授予授权。

### 上下文、投影与布局

三栏共享准确projectId／runId／mode／contextToken；旧读请求和订阅在切换时取消，响应仍核对token。历史快照通过依赖注入不给命令客户端。当前服务端allowedActions控制操作；每次响应撤权时清受保护投影，保留未保存输入的处置提示，不能退回匿名继续请求。

左栏项目／执行选择，中栏已提交消息和输入，右栏固定任务／协作／成果／预览／记录。任务内计划列表、最多30节点DAG和来源使用同一内部导航栈；不生成伪状态。已有逐项审查、预览管理、接受、导出采用准确Run／候选链接，不由打开页面触发副作用。尚未接入的配置／控制用真实缺项说明，不能展示虚构成功。

初始HTTP快照和分页事件可在首增量支持显式刷新与有界补取；这不宣称已实现设计要求的WebSocket。完整步骤另实现同源重新鉴权升级、有界缓冲后补历史、连续seq合并和resync，慢客户端断开重快照。客户端不能依据自由文本变更状态；事件只提示更新，刷新不抢焦点或重置草稿／页签／导航／阅读位置。

### 键盘与窄屏

输入Enter换行，Ctrl／Cmd+Enter提交，IME composition和重复键禁止发送。明确按钮与相同提交锁共享路径。右侧五页签遵循tab语义与方向键，窄屏切左导航／中主区／右详情，顶部当前执行与待办常驻。事件更新不自动聚焦；消息仅在原底部且无文字选择时跟随。

## Risks / Trade-offs

- 浏览器拒绝／清理存储 → 不把内存当已持久，不在原信封保存前发送，不承诺浏览器清理后还能恢复本机未提交草稿。
- 多页竞争与版本变化 → IndexedDB事务CAS、原请求唯一性、当前服务端If-Match和显式陈旧提示；不自动改依据或替换原键。
- 快照消息分页与实时补发 → 保留快照seq与消息游标，有限页预算、按messageId去重，越界或缺口重快照；HTTP补取与WS分别留证。
- 当前无真实模型／身份／Linux → 实际SQLite／HTTP／Edge／IndexedDB与明确夹具分别验证；完整产品路径、真实环境和正式P1-08评审单列。

## Migration Plan

不改控制库SQL、Runner格式、A2A和既有写API。浏览器IDB首次创建schema，版本冲突或blocked状态关闭新命令并提示关闭旧页。后续升级事务保留原信封，不清库规避失败；旧版本遇到新schema须安全关闭。回滚页面代码时保留数据库，不丢未决请求。新入口通过已有Input API装配生效，独立交付页面继续可直接使用。
