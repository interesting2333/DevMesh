## Why

父工作包P1-08，依据实施文档P1-08、设计D3 §4～6和产品路径一／T08。当前已有项目／消息／快照／事件／计划API及独立审查、预览管理、接受、导出React页面，但没有贯通入口，也没有IndexedDB草稿与跨刷新命令日记。用户无法从空项目通过工作台连续使用这些能力。

## What Changes

- 在已有受保护Input API内提供工作台页面与脚本，沿用React、Node、原身份边界与原服务端事实，不新增应用框架。
- 建立三栏与固定五页签、准确项目／Run上下文、窄屏和键盘行为；支持空项目输入、消息、理解／计划／DAG／来源查看及既有审查／预览／接受入口。
- 用原生IndexedDB按当前主体／项目／Run／表单和依据隔离草稿、原提交信封；事务完成前不得标为本地已保存或发送HTTP。多页冲突不能静默覆盖。
- 刷新只核实原提交，未知不生成新键；事件按连续seq补取，迟到上下文响应丢弃，业务更新不覆盖草稿、页签、选中项和焦点。
- 历史上下文从命令依赖层只读。权限失效清除受保护投影，浏览器存储失败保留内存输入并阻止无保护离开。

## Capabilities

### New Capabilities

- `workbench-first-path`: 受保护的工作台入口、上下文、浏览器持久草稿／命令恢复、实际API与已有交付页面导航。

### Modified Capabilities

无。本变更复用原Input API及领域命令语义，不改变A2A、接受、发布和工具准入；新增页面不构成企业身份实现。

## Impact

主要影响packages/input-api的受保护路由、页面与浏览器构建，按需扩展contracts的公开显示契约及测试。复用现有React／Zod／构建器与原生IndexedDB，实时事件服务新增固定ws 8.23.0与类型声明@types/ws 8.18.2，不迁移控制库或Runner格式。项目台账关联P1-08；未满足前置／门槛时只记录已授权开发增量，正式状态保持等待。

验证分为真实HTTP／文件Worker、实际Edge／React／IndexedDB及故障／双页／窄屏行为。完整首次路径须真实模型和Linux资源后另验；当前用户要求未配置这些资源，不能用合成事件或浏览器身份夹具宣布正式验收。
