## Context

P2-03 要求变更排队、影响图、局部冻结、冲突依据、决定／应用／复验和 T3。当前只有契约定义，没有持久化或 API。G1 未通过，因此先实现可离线验证的提案与决定核心。

## Goals / Non-Goals

**Goals**
- 变更提案持久化且同来源消息唯一。
- 决定必须基于当前依据；旧计划／需求派生出的决定被拒绝。
- 确认／拒绝不可从错误状态进入，操作幂等。

**Non-Goals**
- 不实现影响图、局部冻结、应用／复验与 T3 的完整交互。
- 不调用模型生成变更分析。
- 不改变实施 DAG 或接受流程。

## Decisions

1. **依据 hash**：`basisHash = sha256(canonical({runId, planRevision, requirementRevision, resourceRevision}))`，提案时记录；决定时重新计算当前值。
2. **旧依据拒绝**：决定请求的 `basisHash` 必须同时等于当前计算值与提案记录；任一不符返回 `CHANGE_BASIS_SUPERSEDED`，不改变状态。
3. **状态机**：PROPOSED → CONFIRMED／REJECTED；终态不可再决定。同来源消息重复提议返回原回执。
4. **幂等**：提案与决定都是 operation；同键同请求返回原结果。
5. **查询**：按 Run 有界列出；只返回公共投影，不暴露内部路径。
6. **后续**：影响图与局部冻结在拿到真实变更分析后单独实现；`basisHash` 作为其稳定输入。

## Risks / Trade-offs

- 依据可能在决定期间变化 → 以当前计算值比较，拒绝而不是覆盖。
- 没有影响图时确认变更可能过早 → 本增量只记录决定，不自动应用；应用仍独立。
- 真实模型未接入 → 提案正文只来自用户输入，不生成假分析。

## Migration Plan

新增向前迁移，只增加变更提案表与索引；旧库升级保留原数据，失败原子回滚。
