# 候选冻结开发复核

本轮由同一 Codex 实施并进行开发自查，不是独立 T10／产品验收。OpenSpec 4.1、4.2 按本轮实际实现和验证完成，5.1、5.2 仍未完成；正式工作包及 G0～G4 门槛不改变。

迁移 28 为新候选保存不可变冻结日志、正式 Work 证明与内容引用；既有无来源候选不升级为正式证明。CandidateFreezer 实际读取正式评估、角色候选及其 artifact 引用、原报告、交付材料，核对实际字节与哈希。最终事务再次核对当前准确源码、计划／需求／模板／配置、Work 证明、最终 Tester 原质量、交付、未知副作用和高严重问题，防止预检后依据变化。正文最多 192 KiB，与预检哈希清单合计最多 240 KiB；超限拒绝，不截断证明。

冻结追加修订、证明与内容外键，并在同一事务推进 REVIEW、增加资源版本及 CandidateUpdated 事件；不创建 Release，不推进接受指针。事务中断全部回滚，原回执丢失返回同一候选。只有非人工项全部通过的明确人工待审可保留 PENDING，原 Tester 不提前完成；自动 FAIL 不能由人工 PENDING 掩盖。旧报告不能服务新的 SHA，沿用必须有确认快照和原 APPLIED 证明，历史兼容结果拒绝放行。新修订不继承人工决定，旧修订或来源／材料变化显示 STALE，历史正文保持不变。

最终 freezes-v5：typecheck、lint、当前依赖构建及冻结 14/14 通过。此前 freezes-v4：同组检查、Work 验证 11/11、存储 28/28、OpenAPI 一致性均通过。v4→v5 仅冻结详情合计大小守卫与 README 变化；其余检查按文件指纹复用，没有记作重新执行。v1 unused 测试变量 lint 失败、v2 嵌套事务错误、v3 测试构造被正确的候选 head 守卫拦截，均保留原失败报告和当时源码；修复后才记录本轮通过。

实际执行为迁移 SQLite、认证本地 HTTP Runner、PipelineCoordinator、原质量／交付采集、内容 ACK、三个正式 Work 评估和冻结事务。Runner 受控后端写入固定报告／构建／镜像字节，没有执行 Docker；源码 Git／准入／Runtime 候选发布在本组用例中仍是明确数据库夹具。实际 Git 与 Runtime 分别已有其他测试，但不能用它们替代任务 5.1 的同一链路失败→修复→复验→冻结组合。真实模型、OIDC、Linux/gVisor、镜像运行健康、数据迁移、材料语义和脱敏均未验证。

复核覆盖：元数据权限与重放、同事务回滚、不可变触发器、内容外键／GC 互斥、实际文件丢失、预检期间来源变化、准确 SHA、未知作业、高严重问题、人工待审、If-Match、当前／历史查询和接受指针不变。固定提交干净 checkout 与完整组合继续在 5.1、5.2 实施。
