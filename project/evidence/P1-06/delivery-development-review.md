# 原交付来源开发复核

本轮由同一 Codex 实施并进行开发自查，不是独立 T10／产品验收。4.1、4.2、5.1、5.2 继续未完成，正式工作包及阶段门槛不改变。

迁移 27 将交付策略、原质量依据、原 Job、输出索引／哈希／大小与材料 ACK 固定。清单在 Tester 准入前进入质量配置哈希，交付登记不能事后削弱。显式 DeliveryCollector 仅 GET 原 Job 和固定输出，核实构建字节与 OCI 内容身份，再核对规范数据方案；不启动作业、不执行镜像或数据动作，不写接受指针。材料与业务外键在内容 ACK 事务建立，GC 不能删正在引用的内容。丢失内容／最终回执恢复原键和原结果，成员权限在重放时仍检查。

交付数据方案区分无接受版本的初始化、保留并迁移、明确批准的替换。当前验证了初始化、已有数据不能走初始化、准确同 Run 迁移 artifact、无绑定方案决定时替换拒绝；接受历史是测试中显式种入的数据库夹具。负责人替换决定的产品入口及实际数据准备属于后续 P1-07，不宣称本轮已完成。

最终验证：deliveries-v3 交付 12/12、原质量材料 10/10、contracts 18/18、存储 28/28、lint 与 OpenAPI 一致性通过；原采集器 8/8、镜像内容 6/6、typecheck 及当前依赖构建在 deliveries-v2 通过。v2 最后因驱动写错测试文件名停止，原记录保留；v2→v3 只有交付测试文件变化，应用源码相同，未把复用检查记成重新执行。v1 为 6/7，失败是成员夹具少填 created_at；其报告和当时源码快照保留。

实际范围为本地 SQLite、认证 HTTP Runner、输出收集、PipelineCoordinator、原报告计算、内容存储和持久事务。受控后端写入明确的构建／镜像字节夹具，未执行 Docker 构建；Git、准入、Runtime 及接受历史按用例明确种入。不证明真实模型、OIDC、Linux/gVisor、镜像可运行／健康、导出材料语义或脱敏。实际 Runner 收集总量仍是 64 MiB（含日志）；客户端默认 8 MiB，只在显式有界请求时允许 64 MiB。

接下来实施不可变候选修订、当前／历史资格、未知写／高严重缺陷拒绝与人工待审状态，再做完整组合和固定提交干净 checkout 验证。
