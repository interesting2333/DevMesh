# P1-07 人工审查入口开发复核

原候选预览页增加“逐项审查此候选”，受保护的独立 React 页显示准确 SHA、自动检查和必要人工项；显式填写结论、实际操作与观察。新增退回、分类纠正与有理由撤回都追加原历史，页面不执行修复、接受、发布或修改原质量／Work事实。

## 提交与权限

服务端逐请求校验当前成员、负责人、候选／条目 hash、If-Match 与前条结果 CAS。canWithdrawRejections由服务端计算，旧候选只允许适用原退回撤回。新提交先把原正文、UUID和ETag写入当前标签sessionStorage；丢响应／刷新后仅由用户明确核实原请求，不能存储或原记录损坏时关闭新提交。已明确依据不适用的请求，刷新核对后才可放弃填写；未知状态保持原请求。加载和历史分页只GET，单在途、15秒合作取消、离开取消、BFCache恢复重载。撤权清空审查和历史；正文由React按文本显示，nonce CSP与脚本同样鉴权。

## 实际验证

最终接口3/3、实际Edge4/4、原交付页Edge3/3、人工领域／退回／原预览入口／宿主／契约回归39/39，合计49通过、0跳过。构建、类型、Lint和OpenAPI一致性通过；248条源码映射匹配原字节（含TSX与浏览器第三方），绑定647份源码及产物，迁移1～44与Runner未改。

真实本地SQLite Worker／HTTP／React／Edge执行：提交入库后丢响应、刷新、同原键核实，两次请求只一条持久人工结果；接口Worker重启后同原键找回；新请求缺If-Match拒绝、陈旧CAS拒绝；viewer不能写、撤权后JSON／页面／脚本／历史404。退回分类纠正和撤回留下3条记录，恶意文本不执行；21条历史按20／1翻页返回；损坏待核实记录阻止提交，明确清除不会自动提交。原质量和接受事实不变。原交付页实际ZIP下载及响应恢复回归通过。已目视检查桌面1280px和移动390px截图，布局无覆盖或横向溢出。

## 失败与绑定

前两次构建分别发现多入口IIFE不支持、关闭分包仍要求单入口；最终改为两份独立单入口配置，各clean自己的输出子目录，原公开URL不变。接口首轮2/3和浏览器首轮1/3暴露原RELEASE_CANDIDATE_*错误未映射，外项目／撤权候选错误返回503；补404统一映射后复跑全部相关组通过。另一个浏览器失败是测试在待核实按钮出现时过早检查数据库，该按钮在提交前保存原键时即出现；改为等明确丢响应提示后检查，产品逻辑未为此放宽。

首次回归虽39/39但期间修改了尚未构建的review.ts，原记录保留并由最终完整回归替代。最终构建及所有测试／类型／Lint／契约均对应同一输入清单，运行期间和结束核对无源码变化。首轮失败浏览器测试从随后增加损坏记录场景的快照中去除该场景重建，SHA-256与首轮记录完全一致；仅保留列明的失败源快照，不声称完整失败checkout。未执行完整pnpm check。
