# P1-07 退回与分类纠正开发说明

本组继续同一 OpenSpec 的 1.3，新增迁移 31 和私有 Worker 记录／历史查询。每个逻辑退回有稳定 rejectionId；每次提交绑定准确候选、manifest、前一 resultId、操作者、说明、分类依据与同 Run 证据，纠正和撤回均追加保存。原范围缺陷必须绑定现有审查项，新增需求可以没有既有项；两者分别明确提示后续修复审查或变更审查，applicationState 始终 NOT_APPLIED，不自动派发 Work、发布计划或应用变更。

当前人工审查可以全 PASS，但只要同一 Run 仍有 OPEN 退回，接受准备仍不可用，reviewHash 也包含这些原记录。冻结新候选不能隐藏旧待处理项。负责人可以有理由撤回历史候选的已有退回；此操作不为历史候选新增批准、不改原自动结果或任何人工条目，也不默认批准新候选。未撤回而继续处理的问题仍须后续真实修复／变更和新计划流程。

标准 meta、If-Match、当前记录 CAS、项目 owner 权限和跨候选身份检查都在同一 Worker 事务。记录、证据外键、当前指针、操作、资源版本及 CandidateRejected 事件一起保存／回滚；丢回执查询原键，不再次创建退回。Run 最多 100 个逻辑退回，完整投影仍受 1 MiB 上限保护；历史最多 100 条／1 MiB 分页。没有新模型工具或公开服务批准入口。

此阶段仍是后台审查准备，没有人工审查页面、实际预览、dataset 准备、T5 接受或发布消费者。正式 P1-07／阶段门槛状态不改变；D03 的待处理事实与分类历史可验证，完整产品退回→修复／新增范围→接受流程须后续组合与产品验收。

reviews-v5 在当前源码指纹不变期间通过全部适用开发检查：类型、lint、当前 contracts／storage 构建、审查／退回 13/13、冻结 14/14、存储 28/28（包括各旧版本备份升级到迁移 31）、契约 18/18 与 OpenAPI。原日志／哈希见 [reviews-v5/evidence.json](./development/reviews-v5/evidence.json)。新增 5 项退回测试覆盖分类纠正与未应用状态、整个 Run 的旧候选阻塞、有理由撤回且新检查仍待审、owner／CAS／原键恢复、事务切点、内容外键和跨 Run 拒绝；没有把受控夹具当作真实人工或产品验收。
